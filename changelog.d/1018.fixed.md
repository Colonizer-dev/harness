**OpenAI-compatible providers whose base URL ends in `/v3` (BytePlus, Volcengine) work again.** The gateway dropped the request's leading `/v1` only when a base URL ended in `/v1`, so a base such as `https://ark.ap-southeast.bytepluses.com/api/coding/v3` posted to `…/v3/v1/chat/completions` and every call failed as a `502`. A base whose path ends in any `/v<digits>` segment is now treated as the provider's API root on every gateway route (translated chat, the `/v1/responses` and `/v1/chat/completions` passthrough, the anthropic wire and the `/v1/models` health probe); other bases keep the full path appended.
