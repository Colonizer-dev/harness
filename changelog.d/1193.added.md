**Releases can be cut by a release train instead of by hand.** `scripts/release-prep.mjs` does what the release pull requests did: it folds the `changelog.d/` fragments into `CHANGELOG.md`, bumps the release crates to the next patch (a crate such as `colonizer-redact` that is already ahead is left alone), refreshes `Cargo.lock` and writes a release-notes stub, and does nothing when no fragment is pending. The new `Release train` workflow runs daily and by hand: while `main` has pending fragments and its latest CI runs are green it opens `release: vX.Y.Z` with auto-merge on, and after the merge it checks the tag gate, pushes the lightweight tag on the merge commit and dispatches `Release` on it (a tag pushed with `GITHUB_TOKEN` would not start it). `release-train: skip` in the head commit of `main` postpones a run, and only patch bumps are ever made. While a release pull request is open, the merge steward holds colony pull requests that add a fragment. See `docs/release.md`. ([#1193])
