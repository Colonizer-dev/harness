**A long colony opens on its latest messages and loads the older ones as you scroll up.** The colony chat used to fetch and render a colony's whole history before anything showed, which was slow for colonies with thousands of events, on a phone or over remote access. Now the events socket takes `limit` and sends only the newest page of the current run (about 200 events, extended back to the start of the turn it would cut) with a `history` frame saying whether more is behind it, and `GET /api/sessions/{id}/events?before=<seq>&limit=` returns the page before, read from the end of `events.jsonl` and then the rotated `events-N.jsonl` so the cost does not grow with the history. Scrolling near the top loads the previous page and keeps your place, with a "Loading earlier…" row and a "Jump to start" for very long chats; live events stream at the bottom as before. The settler cards, their numbering, the cost and the brief come from a summary the mothership keeps instead of a replay of every event, and a socket without `limit` replays the whole run as before. For 5,000 events the first paint carries 75 KB instead of 1.85 MB. ([#1210])
