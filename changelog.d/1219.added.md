**Trusted auto-colonize: new issues from people the org trusts start by themselves.** Set `auto_colonize` to `trusted` per org (Settings → Workspaces → Colonies → Auto-colonize) or per repository (`PUT /api/repos/{owner}/{name}/auto-colonize`); it is off by default and only issues filed after you turn it on are taken. An author is trusted when GitHub says they are an org member or owner, a collaborator with write access, an allowlisted login (`auto_colonize_allow`) or the signed-in account itself, looked up through the API and cached for five minutes, never read from `author_association`. A stranger's issue, an issue a stranger edited, one labelled `no-colonize` or `needs-human`, and anything in a hidden org never starts by itself; the issues list (`GET /api/repos/{owner}/{name}/issues`) carries `intake: {mode: auto|review, reason, label, author, trusted, …}` on each issue, and `POST …/issues/{number}/intake` dismisses or restores one. A repository starts at most 5 auto colonies an hour (`auto_colonize_rate`), a colony that started this way is checked again at boot, and comments from outside the org are left out of its brief. Every trust decision is a line in the activity log. ([#1219])
