# Colonizer v0.2.10

## Queued colonies can jump the line

Colonies waiting to start now go in order of priority, then age ([#1156](https://github.com/Colonizer-dev/harness/issues/1156)).

- Each org has a **Queue priority** setting: High, Normal or Low.
- On a queued colony, **Move to front** and **Move to back** put that one colony first or last. They are also in the Overview table.
- An org's `max_wait_hours` lifts a colony that has waited too long to High.
- The Nest header says which colony is next up.
- The global, org and per-repository limits still apply.

## The Nest badge counts issues, not pull requests

The frontier badge used to count open pull requests, forks and archived repositories as well, and
on one install it read 2671 ([#1144](https://github.com/Colonizer-dev/harness/issues/1144)). It now counts only open issues in the repositories you colonize, and it
refreshes on its own instead of freezing at page load. The tooltip reads "21 open issues in 5
repositories you colonize".

## Security status

Colonizer is alpha and **not ready for unattended work on sensitive repositories, real credentials
included.** An external audit of v0.1.3 (commit `d89ce76`, 17 September 2026) found four ways a
colony could cross into the host; they are filed as draft advisories (F01–F04) and are **not fixed
yet**, and its four release checkpoints (G1–G4) are all uncleared. Controls added since — scoped
tokens, remote-access fencing, sensitivity-aware routing, gateway audit lines, log and secret
redaction, path policy, egress and exec policies — do not close those findings, so attended work is
what the harness is good for today. The live status is
[docs/audit.md](https://github.com/Colonizer-dev/harness/blob/main/docs/audit.md) and its tracking
issue ([#91](https://github.com/Colonizer-dev/harness/issues/91)); report vulnerabilities privately
through [SECURITY.md](https://github.com/Colonizer-dev/harness/blob/main/SECURITY.md).
