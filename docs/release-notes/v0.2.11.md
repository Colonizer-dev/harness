# Colonizer v0.2.11

## Settings are easier to find

Settings is now one vertical menu with search, and every view in the cockpit has its own address you
can bookmark and share ([#1180](https://github.com/Colonizer-dev/harness/issues/1180)).

- Press `/` to search any page or field by name, help text or a plain word like "key" or "token".
- A dot on a group shows when something needs you (amber) or is broken (red).
- On a phone, the menu is a list that opens each page with a back arrow.

## Fixes

- **Auto mode no longer takes on more colonies than the host can hold** ([#1158](https://github.com/Colonizer-dev/harness/issues/1158)). Running colonies are never stopped; over the limit, nothing new starts.
- **A quota error is blamed on the right provider** ([#1168](https://github.com/Colonizer-dev/harness/issues/1168)), so one provider running out no longer pauses the whole queue as a Claude problem.
- **Providers show their own logo** ([#1166](https://github.com/Colonizer-dev/harness/issues/1166)), even when they were saved as `custom` at a known vendor's URL.
- **No more false alarms for placeholder dotfiles** ([#1169](https://github.com/Colonizer-dev/harness/issues/1169)). The empty `.env` and similar files the harness mounts no longer look like a control bypass.
- **Documented example keys and redacted PR descriptions no longer block publishing** ([#1175](https://github.com/Colonizer-dev/harness/issues/1175)). A colony that is stuck on the same cause now fails fast instead of looping.
- **Helper agents work with model aliases** ([#1176](https://github.com/Colonizer-dev/harness/issues/1176)), and a finished colony is no longer held over an unrecognized model.
- **The Nest shows every colony** ([#1177](https://github.com/Colonizer-dev/harness/issues/1177)), however busy the host is.

## Smaller changes

- The log archive's **Clean up now** takes hours as well as days.
- The Jev key can be set on the Secrets page, without a restart ([#1179](https://github.com/Colonizer-dev/harness/issues/1179)).

## Security status

Colonizer is alpha and **not ready for unattended work on sensitive repositories, real credentials
included.** An external audit of v0.1.3 (commit `d89ce76`, 17 September 2026) found four ways a
colony could cross into the host; they are filed as draft advisories (F01–F04) and are **not fixed
yet**, and its four release checkpoints (G1–G4) are all uncleared. Controls added since — scoped
tokens, remote-access fencing, sensitivity-aware routing, gateway audit lines, log and secret
redaction, path policy, egress and exec policies — do not close those findings, so attended work is
what the harness is good for today. The live status is
[docs/audit.md](https://github.com/Colonizer-dev/harness/blob/main/docs/audit.md) and its tracking
issue ([#91](https://github.com/Colonizer-dev/harness/issues/91)); report vulnerabilities privately
through [SECURITY.md](https://github.com/Colonizer-dev/harness/blob/main/SECURITY.md).
